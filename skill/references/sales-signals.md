# 销售信号口径

这份文件定义「什么算工作」「算到哪一步」「什么不许写」。模型按这里判，脚本只做结构校验。

## 1. 阶段（stage）枚举

固定九个，不许自造。一条事项在同一时刻只属于一个阶段。

| stage | 含义 | 判据（满足其一即可） |
|---|---|---|
| `contact` | 初次接触 | 加了微信、第一次打招呼、客户主动来问，还没有明确需求 |
| `discovery` | 需求确认 | 客户说了场景、痛点、现状、预算范围、决策链 |
| `solution` | 方案 | 我在出方案 / 做 demo / 申请试用 / POC；客户在等 |
| `quote` | 报价 | 出现过具体价格、折扣、阶梯价、账期讨论 |
| `negotiation` | 商务谈判 | 谈合同条款、付款方式、发票、审批流程、比价 |
| `contract` | 签约流程 | 客户明确说在走合同/盖章/打款流程 |
| `delivery` | 交付 | 签约后开通、部署、培训、验收 |
| `won` | 成交 | 客户确认已付款或已签约生效 |
| `lost` | 丢单 | 客户明确说不做、选了别家、项目取消 |

**只能前进，不能凭感觉回退**。客户从 `quote` 退回 `discovery`（重新讨论需求）是真实发生的，允许，但必须在 `status_history` 写清原因。

## 2. 状态（status）枚举

| status | 含义 | 谁来定 |
|---|---|---|
| `active` | 在推进，有下一步 | 模型 |
| `blocked` | 卡在具体一件事上（等审批、等预算、等客户内部决策） | 模型，必须写清卡在哪 |
| `done` | 这条事项完成了（不等于成交，比如「试用环境开通」完成了） | 模型 + 证据 |
| `lost` | 商机丢了 | 模型 + 客户原话 |
| `vanished` | 长期无任何动静，也没有明确死掉 | 脚本 `--suggest` 提示，人工确认 |

`blocked` 不是语气词。写 `blocked` 必须能填出 `blocked_by`：「等客户采购审批」「等我们法务回条款」。填不出来就不是 blocked，是没在管。

## 3. 信号词（参考，不做硬匹配）

用来快速扫窗口稿，最终判断看上下文。

**需求侧**：预算、需求、场景、痛点、现在用的是什么、要解决、上线时间、谁在用

**方案侧**：方案、PPT、demo、演示、试用、测试环境、POC、对接、集成

**报价侧**：报价、价格、折扣、优惠、多少钱、阶梯价、账期、年付、按月

**谈判侧**：合同、条款、付款、发票、专票、盖章、走流程、审批、比价、采购

**签约侧**：签了、盖章了、打款、首款、定金、合同已寄

**风险侧**：再看看、考虑一下、内部再讨论、预算没批、领导不同意、竞品、别家、对比一下、暂时不需要、明年再说、换人了

**丢单侧**：不做了、选了别家、项目取消、预算砍了

## 4. 丢弃清单

以下不进台账，也不进报告正文（统计数字里可以算）：

- 寒暄、节日问候、表情、红包、点赞
- 纯事务：发个地址、改个会议时间、约了但没约成
- 转发的新闻、行业文章、公众号链接（无客户自己的判断）
- 我方单方面发资料、客户零回应 → 算「触达」，不算「推进」。（群里由我方同事代说的进展也算「我方单方面」，同样不算客户回应）
- 系统通知、自动回复、群公告
- 客户问的个人问题（帮忙内推、问路）

**「触达」和「推进」要分开**：一周发了 5 份资料客户都没回，是「触达 5 次、推进 0」，不是「本周跟进了 5 个客户」。

## 5. 金额铁律

这是最容易翻车的地方，单独列。

**允许**：
- 客户说「预算 30 万以内」→ `amount: 300000, source: "客户口述预算"`
- 我方报价「28 万」→ `amount: 280000, source: "我方报价"`
- 客户说「按 25 万签」→ `amount: 250000, source: "客户确认价格"`

**禁止**：
- 客户没说金额，自己估一个
- 用「报价 × 赢率」算加权 pipeline
- 把「30 万以内」写成「30 万」（要写成「≤30 万」）
- 把不同币种混算
- 把试用期免费金额算进成交

`amount` 字段只有 `value`、`currency`、`source`、`evidence_msg_id` 四项。`check_ledger.py` 会拿 `value` 去 evidence 那条消息的原文里找（支持 `300000` / `30万` / `30w` / `30 万` 几种写法），找不到就报 `amount_not_grounded`。

**原文是「30 万以内」时**：值写 300000，`source` 写「客户口述预算上限」，报告里必须写「预算上限 30 万」，不能写「预算 30 万」。

## 6. 风险口径

三类结构风险（脚本给，不用模型判断）：

| 信号 | 阈值 | 报告里的写法 |
|---|---|---|
| `awaiting_me` | 客户最后发言超 `--awaiting-days`（默认 2 天） | 「我欠 X 一个回复（客户 11-24 问…）」 |
| `awaiting_client` | 我最后发言超 `--awaiting-days` | 「X 已 N 天未回（我 11-13 发了…）」 |
| `silent` | 窗口内客户零发言 | 「X 本周期只有我在发，客户零回复」 |

两类语义风险（模型判）：

- **承诺未兑现**：我说了「明天给你」但窗口内没有后续交付 → 写「我方承诺未闭环」，不写「客户不满意」。
- **卡点重复**：同一件事在连续两个周期都被写成 `blocked` → 写「同一卡点已持续 N 周」，这是需要升级的信号。

**不许写**：「客户可能已经放弃」「这个单子希望不大」「客户意向不强」。这些是判断，不是事实。要写给证据，让读者自己判断。

### 6.1 群聊里的三个坑

群里我方同事和客户方混着说话，「客户没回」这句话很容易写错。

| 坑 | 错法 | 正确写法 |
|---|---|---|
| 同事替我回了 | 看窗口里有人在说话，就写「本周与客户沟通密切」 | 先看 `sender_is_external`。同事发言是我方内部动作，不是客户回应 |
| 客户零发言被同事掩盖 | 群里我方 8 条、客户方 0 条，`silent` 会亮 | 写「该群本周期客户方零发言，仅我方在同步进展」，不要写「沟通顺畅」 |
| 分边未知硬下结论 | `client_side_known=false` 时写「客户在等我们排期」 | 写「该群分边未确认（`sender_is_external` 全空），谁在等谁需人工确认」。**宁可漏一条，不要编一条** |

`window.json` 的 `totals.group_sides` 已经把群消息拆成 `me / ours / theirs / unknown`，引用数字时用这一组，不要用 `their_messages`（那个把同事也算进去了）。

群名、群成员的公司归属都算敏感信息。外发版报告只写「某客户项目群」，不写群名全文和成员名单。

## 7. 客户命名

- `client` 用企微侧栏原样名字（`张三`、`张三(某科技)`），不改写、不简写。
- 需要公司名时单独字段 `company`，**只有聊天里明确出现过公司名才填**，不许猜。
- 同名不同公司：按 `conversation_key` 分开，`client` 后面加后缀区分（`张三(某科技)` / `张三(另一家)`），两个 key 不许合并成一个 item。

## 8. 什么时候新建 item vs 更新

| 场景 | 判断 |
|---|---|
| 同一客户，从报价谈到合同 | 同一个 item，`stage` 前进 |
| 同一客户，报价之外又开了个新产品的试用 | 新建 item |
| 同一客户，去年丢的单今年重新接触 | 新建 item（`opened_at` 今年），旧的保持 `lost` |
| 客户换人对接（原对接人离职） | 同一个 item，`status_history` 记一笔「对接人变更」 |
| 同一客户同一主题中断 3 个月后重启 | 同一个 item，`status_history` 记「重启」，不要新建 |

不确定时优先「更新已有」，因为新建会打断 `carry_forward`，让报告看起来像新商机。
