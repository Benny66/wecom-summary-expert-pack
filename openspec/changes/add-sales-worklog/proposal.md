## Why

销售的工作痕迹几乎全在企业微信里，但「把聊天记录变成工作总结」这件事一直没有可用的做法：手写靠回忆、靠翻聊天，一周下来漏掉的推进比记住的多；直接丢给大模型又会编——编金额、编赢率、把客户的「再看看」翻译成「有意向」。

企业微信聊天已经被证明可以稳定采集（`scripts/wecom/`，读屏 + 滚动，落成可复现的 JSONL 仓库），「脚本做确定性工作 + 模型做语义判断 + 硬闸挡住编造」这条链路也是可行的。本变更把这个能力挪到销售自己的视角上：不做知识库，做**一个人对客户的跟进台账**，再从台账切出六种周期的报告。

## What Changes

- 新增技能 `sales-worklog`：采集 → 窗口切片 → 事项台账 → 六种周期报告（日报/周报/月报/季报/半年报/年报），产物是本地 Markdown。
- 新增 `prepare_window.py`：按时间窗把采集仓库切成「按客户分组、按天分段」的可读对话稿，并算出零幻觉的结构信号（谁欠谁一句回复、客户是否零回复）。单聊与客户群都支持；群里按 `sender_is_external` 把消息拆成 我/我方同事/客户方/未标注，分不清时不硬猜。
- 新增 `check_ledger.py`：台账硬闸，含**金额原文核对**——`amount.value` 必须能在它自己声称的 evidence 消息原文里找到（`300000` / `30万` / `30w` 都试），找不到直接报错。
- 采集模块随技能携带（`scripts/wecom/` + `capture_chat.py`），不改采集器本身；`vendor_wecom.sh` 只做上游同步，属仓库维护工具，不进包。
- 六种周期分三组渲染（描述 / 对比 / 评价），季报以上只读月报与台账，不读原始消息。

不改动上游采集器的任何文件。

## Impact

- 新增能力：`skill/sales-worklog`（SKILL.md + 4 份参考 + 3 个脚本）。
- 影响文件：本仓库 `skill/` 全部为新增；`openspec/` 新增本变更。
- 依赖：macOS + 已登录企业微信 + `swiftc`（仅采集）；Python 3.8+ 纯标准库（切片与校验）。**不依赖任何 MCP**。
- 不做的事：不写知识库、不发邮件、不进腾讯文档、不做团队多人协作视角、不做成交预测。
